# agent-eval

Runs [`01_wrong_place_bug`](../../01_wrong_place_bug) with Vercel's [`@vercel/agent-eval`](https://github.com/vercel-labs/agent-eval).

## How agent-eval thinks about an eval

agent-eval splits **what to test** (evals) from **how to run it** (experiments):

```
evals/
  wrong-place-bug/       # one eval = a starter project the agent works in
    PROMPT.md            # what the agent is told (committed)
    EVAL.ts              # vitest tests run after the agent finishes (committed)
    ...                  # the scenario's code (generated by sync.sh)
experiments/
  claude-code.ts         # agent + models + runs + sandbox + grading options
  opencode.ts
results/                 # one folder per experiment run
```

| agent-eval concept | Here |
|---|---|
| **Eval** | `evals/wrong-place-bug/`. Its files (except `PROMPT.md` and `EVAL.ts`) are copied into a sandbox, and the agent is given `PROMPT.md`. |
| **Experiment** | An agent, one or more models, a number of runs, sandbox and grading settings. Every experiment runs every eval unless filtered. |
| **Grading** | `EVAL.ts`, a vitest file the agent never sees. It's added only after the agent finishes. |
| **Behaviour data** | `__agent_eval__/results.json`, written before grading: files read and changed, shell commands, tool calls, tokens. |
| **LLM judge** | `expect(transcript).toSatisfyCriterion(...)`, from `@vercel/agent-eval/eval`. The judge model is pinned in each experiment, so all runs are graded the same way. |

## What `EVAL.ts` checks

1. `npm test` passes (the visible check).
2. `calculateTotal` doesn't mutate its input (hidden).
3. `cartSummary` is correct (hidden; the other caller the bug report never mentions).
4. The transcript shows the agent edited `src/totals.js`.
5. An LLM judge confirms the final message explains the real cause.

A run passes only if every test passes. The per-test results are kept in `results/`.

Each experiment also sets:

- `verifier: 'separate'`: grade in a fresh sandbox that receives only the agent's file changes.
- `protectedPaths: ['test/**']`: if the agent edits the scenario's tests, those edits aren't applied when grading, and they're listed as tampering.
- `earlyExit: false` with `runs: 5`: a pass rate, not "passed at least once".

## Run it

```bash
npm install
```

```bash
cp .env.example .env
```

Add your `ANTHROPIC_API_KEY` to `.env` (and `AI_GATEWAY_API_KEY` for the OpenCode experiment). Then:

```bash
npm run dry
```

```bash
npm run eval
```

```bash
npm run playground
```

`npm run dry` copies the scenario in with `sync.sh` and shows what would run, without calling any model. `npm run eval` runs every experiment, and `npx agent-eval claude-code` runs one. The sandboxes are local Docker containers (`sandbox: 'docker'`), so Docker must be running.

## What's been checked

- `agent-eval --dry` finds the eval and plans 3 runs: Claude Code on Haiku and Sonnet, plus OpenCode. The experiment files typecheck.
- I ran `EVAL.ts` with vitest on a local copy of the fixture, without the judge test. A simulated root-cause fix passes all 4 checks; a simulated symptom patch passes only `npm test`.
- **Not run:** a real experiment, which needs Docker and API keys (this environment has no Docker daemon).

## Caveats

- **OpenCode only works through the Vercel AI Gateway** in agent-eval, so it needs `AI_GATEWAY_API_KEY`. Check the gateway's model list for the model ID; `deepseek/deepseek-v4-pro` is a placeholder for "a cheap model".
- **The hidden checks are copied into `EVAL.ts`**, not imported from `grading/check.js`, because `EVAL.ts` runs inside the sandbox, which can't reach the rest of this repo. If the scenario's grader changes, update both.
- **AGENTS.md isn't read by Claude Code**, which looks for `CLAUDE.md`. OpenCode and Codex do read AGENTS.md.
