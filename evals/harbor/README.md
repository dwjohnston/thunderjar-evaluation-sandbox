# Harbor

Runs [`01_wrong_place_bug`](../../01_wrong_place_bug) as a [Harbor](https://github.com/harbor-framework/harbor) task.

## How Harbor thinks about an eval

Harbor (from the Terminal-Bench team) treats an eval as a **task**: a folder holding everything needed to build an environment, give an agent an instruction, and score what it left behind. A **job** runs one or more tasks against an agent and model, in containers.

```
wrong-place-bug/
├── task.toml              # timeouts, users, network, verifier mode, artifacts
├── instruction.md         # what the agent is told
├── environment/
│   ├── Dockerfile         # the agent's container
│   └── workspace/         # the scenario's code (generated by sync.sh)
├── tests/
│   ├── Dockerfile         # the verifier's own container
│   ├── test.sh            # scores the result, writes /logs/verifier/reward.json
│   └── check.js           # the hidden grader (generated by sync.sh)
└── solution/
    └── solve.sh           # reference fix, used by the `oracle` agent
```

| Harbor concept | Here |
|---|---|
| **Instruction** | "Fix the issue described in ISSUE.md." |
| **Environment** | `node:22-bookworm` with the scenario in `/app`, committed as a git repo. The agent runs as the non-root `node` user. |
| **Verifier** | `tests/test.sh`, in a **separate** container. Harbor copies the agent's `/app` out as an artifact and recreates it there, so the agent never sees the grader and can't change it. |
| **Reward** | `reward.json`: `reward` (1 only if both checks pass), `visible_tests`, `root_cause` |
| **Oracle** | `solution/solve.sh`. `harbor run -a oracle` proves the task is solvable and the verifier gives the fix full marks. |

## Run it

Needs Docker and [Harbor](https://pypi.org/project/harbor/) (`uv tool install harbor`).

```bash
./sync.sh
```

Check that the task works, using the reference fix:

```bash
harbor run -p wrong-place-bug -a oracle
```

Run a real agent:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

```bash
harbor run -p wrong-place-bug -a claude-code -m anthropic/claude-haiku-5-5 -k 5
```

`-k 5` runs 5 attempts, for a pass rate. Swap `-a` and `-m` to compare harnesses and models; Harbor ships agents for `opencode`, `codex`, `aider`, `goose` and many more (`harbor run --help` lists them). Results land in `jobs/`. Browse them with `harbor view jobs`.

`sync.sh` copies the scenario into the task (code without README and `grading/` into `environment/workspace/`, grader into `tests/check.js`). Those copies are git-ignored, so rerun it after changing the scenario.

## What's been checked

- `harbor lint` passes on the default rules.
- I ran `test.sh` and `solve.sh` on a local copy of `/app` (no Docker here). The oracle fix scores `reward 1`, the symptom patch scores `visible_tests 1, root_cause 0` (`reward 0`), and an untouched workspace scores all 0.
- **Not run:** `harbor run` itself, with either the oracle or a real agent, because this environment has no Docker daemon.

## Caveats

- **Images aren't pinned.** `harbor lint --extend-select ALL` asks for `FROM` lines pinned to a SHA-256 digest. I couldn't look one up (Docker Hub rate-limited the request). Pin them before relying on results over time.
- **AGENTS.md isn't read by Claude Code**, which looks for `CLAUDE.md`. Other agents, such as OpenCode and Codex, do read AGENTS.md. That makes harness comparisons on AGENTS.md-driven scenarios (00, 03, 04) uneven.
- The agent's container has public network access (`network_mode = "public"`), since agents need to reach their model API.
